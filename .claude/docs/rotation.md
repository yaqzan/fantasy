# Rotation / injury minutes

Goal: predict a player's minutes/FPTS from teammates' absences; surface as an "Opportunity" indicator and feed the optimizer.
Code: `rotation_data.py` (pull + cache under gitignored `.horizon/rotation/`), `rotation_backtest.py` (walk-forward, 2025-26 train, 2026-27 test);
the shipped model is `role_minutes.py` (section "Role-aware minutes", below), the live sheet `nba_rotation.py`.

## Data sources (probed 2026-11-02)
- **NBA daily lineups JSON** `stats.nba.com/js/data/leaders/00_daily_lineups_YYYYMMDD.json` (browser UA + `Referer: https://www.nba.com/`): per game, every rostered player with `rosterStatus` Active/Inactive and `position` set only for the 5 starters. Same ids as `game_lines.player_id`. Works back to at least 2025-26, so it is the **pregame** history we lack elsewhere (`players.injury_status` is current-only). Missing day = 403/404 = no games.
- ESPN depth chart (`espn.com/nba/team/depth/_/name/<abbr>`, core API `.../seasons/2027/teams/{id}/depthcharts`): editorial, current only, goes stale (a Celtics PF starter was wrong). Tiebreak at most, not worth ingesting yet.
- ESPN injuries JSON `site.api.espn.com/apis/site/v2/sports/basketball/nba/injuries` (curl with browser UA; WebFetch gets 403): current only, snapshot on a schedule if wanted. NBA injury-report PDFs (`ak-static.cms.nba.com/referee/injury/Injury-Report_YYYY-MM-DD_HH_MMPM.pdf`) are the only archived Probable/Questionable history.
- Skip Rotowire, Basketball-Reference, Cleaning the Glass (ToS forbid scraping).

## Backtest findings
- Baseline = mean of last 10 played games (+ last-season mpg prior). It **sums to 244-276 team minutes** (only counts games played), and **~1.7 Active players per game with baseline >= 5 min play 0** (DNP-CD). Those two are most of the minutes error (MAE 6.6 train / 9.2 test).
- Naively adding "freed minutes" of Inactive rotation players on top of the baseline made it WORSE (baseline already absorbs absences). Don't do that.
- What helps: normalize active players to 240 (alpha 0.75) **and tilt toward tonight's starters** (gamma 0.5): train new-absence MAE 6.61 -> 6.39, test 9.19 -> 8.55. Gain is the same in games with no new absence, so it is team-total + starter structure, **not an injury-specific effect yet**.
- Position-group tilt toward the absent player's group (beta): no gain at any strength. Position-blind is as good with this data.
- 2026-27 has only 94 new-absence team-games; cannot prove an effect there. 2025-26 (2,476 team-games) is the training set.

## Round 2 (2026-11-02)
- **Play probability** (logistic on baseline, starter, DNP rate over last 6 Active games, minutes freed, Active count): AUC 0.87 train / 0.77 test. Starter (+3.3) and recent-DNP rate (-3.4) carry it. Expected minutes = P(play) x baseline, then 240 + starter tilt: test all-active MAE 8.10 -> 7.09 (train flat at 6.2). 2026-27 play rate is 69% vs 84% in 2025-26 (early-season bloated actives), so retrain as the season fills in.
- **The injury effect is real but small.** Played players, residual vs baseline, cluster bootstrap by team-game, per 10 baseline minutes of NEW rotation absence (Inactive now, Active in one of last 3 games): starters +0.58 [+0.52,+0.63] train, +0.42 [+0.28,+0.57] test; bench +0.29 train, ~0 test; same position group +0.24 train, +0.30 test (CI excludes 0 in both). A 30 mpg starter out is worth about +1.7 min to a starter, +0.9 to a bench man, +0.7 more to his position group.
- **Out of sample (fit 2025-26, score 2026-27, played players, baseline >= 8) the injury terms do not beat a plain intercept+starter fix on MAE** (5.03 vs 5.02; RMSE 6.47 vs 6.49). Most of the gain over baseline (5.22) is the intercept (baseline overshoots by ~2 min) and the starter bump. 94 new-absence team-games is too few to separate the injury part.
- **Next-man-up by minutes rank is NOT supported.** Bench rank 1-2 gains +0.30/10 freed min, rank 3-4 +0.67, rank 5+ +0.78 (train; test same direction, smaller). The effect is diffuse, not a single backup.
- Takeaway for the UI: a per-player "Opportunity" number would be small (usually under 2 min) except when a star sits. Worth showing as a sortable delta, but the value is in star-out nights and in the P(play) / starter-status flag (inactive/DNP risk), which move projections more than redistribution does.

## Shipped (2026-11-03): live "Opp" + play-risk
Files: `nba_rotation.py` (fetch, `Context`, `compute_team`, poller; NOT `rotation.py`: an Archivist `rotation.py` on the machine's Python path shadowed it and crashed the server), `rotation_model.json` (fit by `rotation_fit.py`, refit monthly), `rotation_score.py` (scores logged picks), tables `nba_lineups` + `rotation_picks`.
- A daemon thread (`nba_rotation.start_poller`, started in `backend/app.py`) backfills missing days of `nba_lineups`, then refreshes the next unfinished slate (today, else tomorrow Eastern): every 10 min with games pending, 20 min when nothing is published, 1 h once all are final. Each round also calls `injury_reports.maybe_snapshot()` (3 h) and `depth_charts.maybe_snapshot()` (20 h). `/fantasy` only reads `get_state()` (dict lookup); the state is ignored when older than 3 h or for a past day. No lineup posted = no `rotation` field = no Opp column (and the two filters are inert).
- NBA endpoint: a day with no games = 200 + tiny body; an unpublished day = 302; 403 = a block (error, old state kept). The sheet lists long-term injured players `Active` and marks everything `Confirmed`, so: "new absence" = Inactive tonight (or Yahoo O/INJ) and PLAYED in one of the team's last 3 games (not merely Active: that made every Pacer +1 min a night for a month); Yahoo Q/D/P discounts P(play) for non-starters even when Confirmed (starters only while Expected).
- Payload per player: `p` (P(play), shipped logistic), `base`, `starter`, `promoted`, `confirmed`, `exp` (team-normalised, logged only), and since the role model (`nba_rotation.role_opp`): `opp` = role_minutes' minutes delta against what THE projection carries (the optimizer's factor, capped +-10), `mif` = role_minutes' own minutes if he plays, `rm_exp` (same), `why` (one line, "Duren out (back ~Nov 9): +8 min"), `back` (that teammate's ESPN return date), `out` (the teammates behind it). Points leagues, `/api/fantasy` adds `fpts` (projected FPTS x that factor) and `gain` (vs projected). UI: Player Rankings columns "Opp" (sortable), points leagues "Tonight" (expected FPTS if he plays, sorted by p x fpts, `*` = lineup not confirmed) and "ROS", placed right after FPTS (phones scroll sideways to Δ / L5 / L10 / GP; headers show no sort arrow on phones; "Tngt" on phones); chips for p < 60% / "Out tonight" / "Starting"; filters "Opp +2 min" and "Likely to play" (p >= 0.8). The phone-first view is the **Tonight tab** (`TonightPickups.js`): cards ranked by expected FPTS x p (or FPTS gain / minutes gain), free agents and likely-to-play on by default, the one-line reason under the name only when his net change vs his projection is >= +0.5 min (a teammate's absence can still net negative). `why` names the absent teammate as "J. Williams" (initial + surname: two Williams on one team).
- Live-path replay 2026-10-27..11-02 (`.horizon/role-minutes/replay_live.py`, final sheets, today's rosters/statuses, n=1,167): minutes-if-plays MAE role_minutes 4.54, shipped mif 4.69, baseline 5.01; shipped base + shipped terms + the role delta 4.79 (so `mif` is the role model's, not a sum). Where |Opp| >= 2 (n=511): 4.76 / 5.02 / 5.40.
- Check it live with `python rotation_score.py` after a few game nights: calibration by P(play) bin, baseline vs mif MAE, and mean (actual - baseline) for Opp >= 2 vs the rest.

- **Optimizer feed (narrow).** `Week.__init__` calls `nba_rotation.tonight_doubtful`: a player the NBA sheet CONFIRMS as tonight's starter (game not started, state day = today ET, state < 3 h old) is removed from `week.doubtful`, i.e. his guessed Yahoo Q/D chance is dropped. Removal only. CLI runs (`lineup_optimizer.py`, `claim_planner.py`) have no poller state and see Yahoo's dict unchanged.

Design if wanted: `week.doubt_day = {name: today}` for the entries written, and apply the factor at those five sites only when `nxt == doubt_day.get(p, nxt)`. Also keep Yahoo's number for bench/unconfirmed doubtful players (the model p already prices ordinary DNP risk, which the 0.86 availability layer counts again).

## Role-aware minutes (2026-11-03): `role_minutes.py`
Research `.horizon/role-minutes/` (NOTES.md; build.py, walk2.py, hazard.py, evaluate.py, future.py, streamers.py, export.py -> `role_minutes_model.json`).
Data: game logs 2013-14..2025-26 (`.horizon/preseason-2026/data/rs_*.csv`; MySQL `game_lines` holds 2026-27 only). Absent = on the team (stints from the log, extended to the season start/end when he was with that team the season before/after) and no line. Minutes normalised to 240 (OT). Log-inferred absences of rotation players (H >= 10) vs the 2025-26 sheet: 63% Inactive, 36% Active-but-DNP (sheet lists long-term injured Active; DNP-CD), 0.6% not listed.
- **Model** (per player who plays): `H + b0 + bH H + bS starter + sum_c coef_c (X_c - Xemb_c)/10 + sum_j delta_ij (o_j - w_ij)`. H = recency-weighted minutes (half-life 10 games, last season's mpg = 5 games). X = absent teammates' H shared over who plays: `role` (H x exp(-profile distance / 1); profile = per-36 REB AST BLK 3PM heavy, FGA FTA STL TOV PF light, z vs last season) and `equal`, each split bench / starter (top-5 H). Xemb = the same over his own past games (the dF idea per channel: what H already contains). delta_ij = empirical on/off pair effect, online ridge (shrink 10) on the linear residual this season; w_ij = recency share of his games j was out.
- **Walk-forward, next game** (fit on seasons before; 73,753 rows 2023-24..2025-26; MAE, 90% team-game cluster CI): baseline last-10 5.031; shipped Opp 4.976; dF 4.863; allocation without similarity 4.758; role-aware 4.781; allocation + pair 4.620; **role-aware + pair 4.633** (-0.40 [-0.42,-0.38] vs baseline, -0.23 vs dF). **That counts every absence the logs show, including DNP-CDs nobody knew pregame. Knowable before tip-off only (2025-26, review 2026-11-04, `.horizon/review-role-minutes/walk_known.py`): role+pair -0.237 [-0.272,-0.206] vs baseline, no-similarity+pair 4.772 vs 4.779 (a tie); the share-out channel alone is nearly all hindsight (-0.019 [-0.072,+0.028]).** Quote that number, not -0.40. Per-date Spearman .763 -> .802. 2026-27 (n=2,145): 5.305 / 4.973 / 4.952 / 4.925 / 4.887 / 4.834 / **4.800**.
- **Role similarity: a tie overall, a win where the owner's hypothesis lives.** Role vs no-role (both + pair): +0.014 [+0.008,+0.019] worse on all 2023-25 rows, but -0.053 [-0.101,-0.009] for bench successors of a 15+ mpg absence, -0.229 [-0.378,-0.060] for the bench successor of a NEW 30+ mpg absence (n=492, actual - H +4.4 min there), -0.034 [-0.056,-0.011] on 2026-27. Shipped role-aware for the pickup use case. The pair term is most of the gain (successor slice 5.05 dF -> 4.69). Old "next-man-up by minutes rank" finding stands; similarity + empirical pairs is what works.
- **Future nights**: next-game coefficients on forecast availability (hazard only) tie the baseline over 7 days; a refit on forecasts (`coef_future`) ties it too (2023 +0.009, 2024 -0.064 [-0.112,-0.013], 2025 +0.004). With the TRUE availability of each night (perfect return dates) role+pair is -0.43 [-0.47,-0.39] vs baseline (3.74 vs 4.17). So the value is in knowing who is out: ESPN dates / Yahoo O / tonight's sheet, not in the hazard.
- **Availability per future night** (`Season.p_out`): tonight's sheet (Inactive 1.0, Confirmed starter 0); ESPN Out with a "long" date: 1 - SLIP cdf(d - return date); a "short" date (placeholder): the game-log table, floored at .85 before the date; Yahoo O/INJ without a date: table, next game >= .9; Yahoo/ESPN day-to-day: next game 1 - DAY_TO_DAY_CHANCE, then the table; else the table: P(out k team games ahead | missed s straight) (out_k, by H band; players come back and sit again, so continuous-spell survival under-states it: after a 1-game absence 0.40 still out 4 games later vs 0.19) or the base miss rate by H band (H 5-10: .37, 10-20: .14, 20+: .05 next game). Tables fit on 2013-14..2022-23.
- **Optimizer factor** (`role_minutes.factors`, `Week.minutes_factor`): per (player, day) `(MIN{suffix} + delta) / MIN{suffix}`, clipped .5-2.0, players under 4 MPG none. delta is against what THAT stats choice carries (`_projected`: `inseason.minutes_weights`, THE one definition the projection's minutes use too (spec U: prior 64/(1+n/80) games, game a back 1 + 16 x 2^(-a/5)); the prior's context is a typical night, xbar; `H` as fit); **only `_projected` is served** (`factors()` returns {} for Season / Last 5 / Last 10: their stats carry no `MIN` key and a delta against a different minutes basis would be wrong). **Served for the team's next `FORECAST_GAMES` = 4 games only; further out the factor is 1.0.** Deltas are centred by `role_minutes_model.json['center']` (tonight/forecast x starter/bench), see "Centre, x0, horizon" below. Tonight with the sheet posted uses the next-game coefficients, other nights `coef_future` and offsets. Season walk cached per day (two kept: the poller asks for tomorrow, the web for today), rebuilt when `game_lines` change (checked every 15 min); ~0.3 s build, ~0.3 s for a week of factors.
- **ESPN depth chart** (`depth_charts.py`, table `depth_charts`): **weight 0 since the 2026-11-04 review** (`depth_boost` 0.0; the code path stays, snapshots keep accruing, once per 20 h after the lineup refresh). Score it forward (~mid-December, 6 weeks of charts, charted backup vs profile-nearest gain) before turning it on again. Until then: the first player listed behind the absent one got 2x role weight (`depth_boost` 1.0). On 2026-27 new absences (n=148 where they disagree, 90% of the time) the charted successor gained +1.25 min vs H, the profile-nearest -0.42 (diff +1.68 [+0.38,+2.99]): **the chart won**, but it is today's chart (flatters it). Live replay MAE: boost 1.0 4.553 vs 0 4.544 overall, 4.671 vs 4.763 where |Opp| >= 2; 3.0 worse both. Empirical pairs take over with games.
