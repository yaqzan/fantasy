# Rotation / injury minutes (research, not shipped)

Goal: predict a player's minutes/FPTS from teammates' absences; surface as an "Opportunity" indicator.
Code: `rotation_data.py` (pull + cache under gitignored `.horizon/rotation/`), `rotation_backtest.py` (walk-forward, 2025-26 train, 2026-27 test).

## Data sources (probed 2026-11-02)
- **NBA daily lineups JSON** `stats.nba.com/js/data/leaders/00_daily_lineups_YYYYMMDD.json` (browser UA + `Referer: https://www.nba.com/`): per game, every rostered player with `rosterStatus` Active/Inactive and `position` set only for the 5 starters. Same ids as `game_lines.player_id`. Works back to at least 2025-26, so it is the **pregame** history we lack elsewhere (`players.injury_status` is current-only). Missing day = 403/404 = no games.
- ESPN depth chart (`espn.com/nba/team/depth/_/name/<abbr>`, core API `.../seasons/2027/teams/{id}/depthcharts`): editorial, current only, goes stale (a Celtics PF starter was wrong). Tiebreak at most, not worth ingesting yet.
- ESPN injuries JSON `site.api.espn.com/apis/site/v2/sports/basketball/nba/injuries` (curl with browser UA; WebFetch gets 403): current only, snapshot on a schedule if wanted. NBA injury-report PDFs (`ak-static.cms.nba.com/referee/injury/Injury-Report_YYYY-MM-DD_HH_MMPM.pdf`) are the only archived Probable/Questionable history.
- Skip Rotowire, Basketball-Reference, Cleaning the Glass (ToS forbid scraping).

## Backtest findings
- Baseline = mean of last 10 played games (+ last-season mpg prior). It **sums to 244-276 team minutes** (only counts games played), and **~1.7 Active players per game with baseline >= 5 min play 0** (DNP-CD). Those two are most of the minutes error (MAE 6.6 train / 9.2 test).
- Naively adding "freed minutes" of Inactive rotation players on top of the baseline made it WORSE (baseline already absorbs absences). Don't do that.
- What helps: normalize active players to 240 (alpha 0.75) **and tilt toward tonight's starters** (gamma 0.5): train new-absence MAE 6.61 -> 6.39, test 9.19 -> 8.55. Gain is the same in games with no new absence, so it is team-total + starter structure, **not an injury-specific effect yet**.
- Position-group tilt toward the absent player's group (beta): no gain at any strength. Position-blind is as good with this data.
- 2026-27 has only 94 new-absence team-games; cannot prove an effect there. 2025-26 (2,476 team-games) is the training set.

## Round 2 (2026-11-02)
- **Play probability** (logistic on baseline, starter, DNP rate over last 6 Active games, minutes freed, Active count): AUC 0.87 train / 0.77 test. Starter (+3.3) and recent-DNP rate (-3.4) carry it. Expected minutes = P(play) x baseline, then 240 + starter tilt: test all-active MAE 8.10 -> 7.09 (train flat at 6.2). 2026-27 play rate is 69% vs 84% in 2025-26 (early-season bloated actives), so retrain as the season fills in.
- **The injury effect is real but small.** Played players, residual vs baseline, cluster bootstrap by team-game, per 10 baseline minutes of NEW rotation absence (Inactive now, Active in one of last 3 games): starters +0.58 [+0.52,+0.63] train, +0.42 [+0.28,+0.57] test; bench +0.29 train, ~0 test; same position group +0.24 train, +0.30 test (CI excludes 0 in both). A 30 mpg starter out is worth about +1.7 min to a starter, +0.9 to a bench man, +0.7 more to his position group.
- **Out of sample (fit 2025-26, score 2026-27, played players, baseline >= 8) the injury terms do not beat a plain intercept+starter fix on MAE** (5.03 vs 5.02; RMSE 6.47 vs 6.49). Most of the gain over baseline (5.22) is the intercept (baseline overshoots by ~2 min) and the starter bump. 94 new-absence team-games is too few to separate the injury part.
- **Next-man-up by minutes rank is NOT supported.** Bench rank 1-2 gains +0.30/10 freed min, rank 3-4 +0.67, rank 5+ +0.78 (train; test same direction, smaller). The effect is diffuse, not a single backup.
- Takeaway for the UI: a per-player "Opportunity" number would be small (usually under 2 min) except when a star sits. Worth showing as a sortable delta, but the value is in star-out nights and in the P(play) / starter-status flag (inactive/DNP risk), which move projections more than redistribution does.

## Shipped (2026-11-03): live "Opp" + play-risk
Files: `nba_rotation.py` (fetch, `Context`, `compute_team`, poller; NOT `rotation.py`: an Archivist `rotation.py` on the machine's Python path shadowed it and crashed the server), `rotation_model.json` (fit by `rotation_fit.py`, refit monthly), `rotation_score.py` (scores logged picks), tables `nba_lineups` + `rotation_picks`.
- A daemon thread (`nba_rotation.start_poller`, started in `backend/app.py`) backfills missing days of `nba_lineups`, then refreshes the next unfinished slate (today, else tomorrow Eastern): every 10 min with games pending, 20 min when nothing is published, 1 h once all are final. `/fantasy` only reads `get_state()` (dict lookup); the state is ignored when older than 3 h or for a past day. No lineup posted = no `rotation` field = no Opp column (and the two filters are inert).
- NBA endpoint: a day with no games = 200 + tiny body; an unpublished day = 302; 403 = a block (error, old state kept). The sheet lists long-term injured players `Active` and marks everything `Confirmed`, so: "new absence" = Inactive tonight (or Yahoo O/INJ) and PLAYED in one of the team's last 3 games (not merely Active: that made every Pacer +1 min a night for a month); Yahoo Q/D/P discounts P(play) for non-starters even when Confirmed (starters only while Expected).
- Payload per player: `p`, `mif` (minutes if he plays), `base`, `opp` (injury terms only, capped at 6 min), `starter`, `promoted` (starts tonight, started <=1 of last 5), `confirmed`, `out` (up to 4 names), `exp` (validated team-normalised minutes; logged, not shown yet). UI: desktop "Opp" column (sortable, nulls last), chips for p < 60% / "Out tonight" / "Starting", phone inline +Xm at |Opp| >= 2, filters "Opp +2 min" and "Likely to play" (p >= 0.8). Points leagues add "about +X FPTS at his last-10 rate" to the tooltip.
- Replay on 2026-10-27..11-01 through the live path (no Yahoo history, final sheet): minutes-if-plays MAE 4.69 vs baseline 5.00 (n=840); mean P(play) 0.82 vs 0.87 actual. Holdout fit MAE 4.88 vs 5.22.
- Check it live with `python rotation_score.py` after a few game nights: calibration by P(play) bin, baseline vs mif MAE, and mean (actual - baseline) for Opp >= 2 vs the rest. If Opp >= 2 players do not beat the rest by >0, the redistribution terms are noise: drop to P(play) + starter only.

## Round 3 (2026-11-03): rate bump + optimizer feed
- **Per-minute rate** (2025-26, 20,785 played-player rows, generic FPTS/min vs his last-10 rate, cluster bootstrap): +0.77% [+0.50,+1.08] (starter), +0.73% [+0.30,+1.15] (bench) per 10 freed minutes of NEW absences; position-group term +0.08% [-0.42,+0.64] (nothing). One global elasticity, `RATE_PER_10 = 0.75`, payload `rate_pct = 0.75 * min(new-absence min/10, 6)` (max 4.5%). Tooltip only (points leagues): FPTS gain = L10 FPTS/min x (opp + mif x rate_pct/100); a 30 mpg starter out is about +1 FPTS. Not in the Opp sort. Measured on 2025-26 only: `rotation_score.py` prints FPTS/min change vs his last 10 for rate_pct >= 1.5 against the rest; drop the bump if it is <= 0 on 2026-27.
- **Optimizer feed (narrow).** `Week.__init__` calls `nba_rotation.tonight_doubtful`: a player the NBA sheet CONFIRMS as tonight's starter (game not started, state day = today ET, state < 3 h old) is removed from `week.doubtful`, i.e. his guessed Yahoo Q/D chance is dropped. Removal only. CLI runs (`lineup_optimizer.py`, `claim_planner.py`) have no poller state and see Yahoo's dict unchanged.
- **Deliberately NOT done: Inactive-tonight -> chance 0.0.** `doubtful` means "his next game after the first eligible day", not "tonight": a 0.0 would zero tomorrow's game for a free agent on waivers until tomorrow (`claim_planner.py` ~318), every `_split_doubtful` add-window copy (~429), an IL player activated tomorrow (`_solve_one` ~450), and the judge / `player_week_games` windows (`player_stats.py` ~420, `claim_planner.py` ~740). Design if wanted: `week.doubt_day = {name: today}` for the entries written, and apply the factor at those five sites only when `nxt == doubt_day.get(p, nxt)`. Also keep Yahoo's number for bench/unconfirmed doubtful players (the model p already prices ordinary DNP risk, which the 0.86 availability layer counts again).
